# Versioned procedure-confirmation register

`PROCEDURE_CONFIRMATIONS_FILE` optionally names an operator-owned JSON array loaded at startup. It is not an institution/officer HTTP input. Each record requires id, scope, exact procedureSHA256, sourceSHA256, HTTPS sourceURL, issuerConfirmationReference, interpretationReviewReference, reviewedBy, confirmedAt, expiresOn and verificationContext. The procedure must declare matching sourceSHA256 and interpretationReviewReference; its entire interpreted DAG/version/period must hash identically. Missing, changed, expired, future, duplicate-active or mismatched records remain human-review blockers. Activation/binding accepts configured references only; client issuerConfirmed flags are rejected by the global privilege-input guard.

The two contexts are INDEPENDENT_ISSUER_CONFIRMATION and SYNTHETIC_CONTRACT_TEST. Contract mode is restricted to explicitly synthetic-* scopes and remains classified SYNTHETIC, issuerConfirmationRecorded=false, realRegulatoryAuthority=false. Independent context represents a separately obtained and reviewed issuer confirmation recorded by trusted operators; the effective classification aligns with the policy engine's ISSUER_VERIFIED classification. It is not automatic issuer authentication, a live issuer API connection, rule interpretation approval, administrative approval or bank release. Operators must actually validate the source/correspondence and interpretation before configuring this context. Test/loopback source URLs cannot be configured as independent confirmations. The default register is empty, actual AICTE policies/procedures remain unverified, and no real confirmation was invented or loaded by this work.

Activation/binding events retain the confirmation state and provenance, protected by their audit payload hashes. Current source snapshots include the exact applicable register state, so revocation or effectiveness changes invalidate stale department responses/proposals/decisions. Administrative approval still requires current review, source evidence, resolved high findings, matching independently trusted policy configuration, mandatory clearances and a distinct checker. External release stays NOT_CONFIRMED.

Read-only scenarios freeze the relevant confirmation candidates and reassess their validity at the explicitly chosen date. A snapshot captured while a synthetic contract was configured remains exactly reproducible after current configuration revocation; it cannot authorize a current decision.
