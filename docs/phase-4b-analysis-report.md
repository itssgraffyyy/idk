# Phase 4B relationships and read-only scenarios

Schema 18 adds independent immutable legal-entity declaration revisions and analysis snapshot/result records. Existing cases, obligations, instruments, documents, hashes, evaluations and migrations remain intact. No graph database or stack migration.

`src/evidence-relationships.js` applies the existing full-case authorization predicate to every cross-record scope. Department-only grants do not expand full-case access. Institution-declared sponsor jurisdiction/registration links already-accessible institutions; matching names alone do not establish identity. Declarations are unverified, source-referenced and revision guarded. Relationship nodes cover institution, sponsor, profile programmes/approval history, obligations, instruments, branch identifiers, logical documents/versions, extraction observations, external evidence, policy checks, findings, clarifications and administrative history. Finding/evaluation source references link back to protected source versions.

Signals flag matching deposit identity, conflicting amounts/holders, related/multiple obligations, legitimate repeated bytes, missing version predecessor, changed extracted facts across versions, replacement timing and cycles. Signals are deterministic review requests, never fraud or bank confirmation. Limits are explicit:500 authorized cases,5000 instruments/versions/edges,500 root evidence and clearance events; maximum10000 output nodes/links/signals. Above-bound scopes return413 with no partial clean assessment. Current assignments determine visibility on every read.

`src/scenario-analysis.js` freezes case/input/obligation/instrument revisions, current source versions/hashes, current extraction/evidence references, accepted proof references, trusted policy capsule, departmental responses/source currency and unresolved administrative blockers. Scenarios change safe integer paise, inclusive dates, registered instrument amounts/dates, add/remove hypothetical instruments, pinned policy versions and explicitly hypothetical departmental statuses. INR only, no currency inference, no pooling, conflicting duplicates excluded, identical deposits counted once, proposed replacements remain excluded. Snapshot configuration/effective periods and source trust gates remain intact. Missing or conflicting applicability evidence stays explicit. Baseline comparison uses the recorded period when present; otherwise the assumed period is disclosed. Snapshot and scenario storage is separate from operational evidence; only analysis records and audit entries are written.

`src/analysis-api.js` authorizes each capture/read/history/replay, rejects stale capture, hashes immutable payloads, binds scenarios to the exact same-case snapshot, and requires exact replay output equality. Algorithm changes may make exact replay unavailable; the recorded original is retained and the API fails explicitly rather than claiming reproduction. Revoked assignments immediately prevent access. Audit reviewers can inspect/replay but cannot create analysis. Audit logs record IDs/hashes, not financial payloads or credentials. These hashes are content integrity checks, not protection against a database administrator; cryptographic audit integrity remains Phase4C work.

The existing case portal has collapsed relationship/source tables, protected viewer navigation, unverified sponsor administration, typed form controls for hypothetical amounts/dates/add/remove/policy/clearances, baseline comparison, saved analyses and exact replay. No operational approval or bank release action is exposed by the simulator.
