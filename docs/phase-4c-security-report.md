# Phase 4C audit integrity implementation checkpoint

Implementation is under validation, not overall Phase4C acceptance. Schema19 adds immutable audit genesis and HMAC-SHA256 seals. Complete canonical audit columns, increasing IDs, previous MAC and payload digest are signed by application-only SQL functions in an AFTER INSERT trigger, atomically with every event, including reminder delivery savepoints. Evidence and departmental audit events include payload hashes. Application transactions checkpoint after commit; ordinary audit writes checkpoint after insert; shutdown closes the database even if checkpointing fails. Startup verifies before accepting work. `scripts/verify-audit.js` opens a read-only database; privileged API returns validity/trust without global counts or event identifiers.

Legacy rows, IDs and bytes remain unchanged. Their enrollment hash/count are explicitly signed as an initial baseline; their pre-enrollment authenticity cannot be retrospectively established. Missing keys/checkpoints or root mismatch never silently reenroll existing history. Default key/checkpoint files are outside SQLite under DATA_DIR/security. Operators can configure AUDIT_KEY_FILE and AUDIT_CHECKPOINT_FILE to independently protected locations; neither a separate pathname nor Unix mode0600 proves Windows ACL or independent custody. An attacker controlling signing key and anchors, or trusted application code/OS, can forge history. No blockchain/immutable-storage claim.

Checkpoint replacement flushes a temporary file before atomic rename. SQLite commit and filesystem replacement cannot be one atomic transaction: a crash after commit can leave a fully signed extension past the last checkpoint. Startup authenticates the entire extension and advances the checkpoint. Loss of a tail never included in a surviving checkpoint is outside truncation-detection guarantees. A checkpoint failure after commit returns an explicit persisted-action inspection error; callers must inspect before retrying. Deleting or replacing a protected checkpoint fails closed and needs explicit operator recovery; no automatic anchor reset exists.
