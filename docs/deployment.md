# Local deployment and recovery

Use Node 22.14 or later supported Node 22. Run `npm ci`, `npm run setup`, then `npm start`. Setup prints credentials only for newly created accounts; re-running it preserves passwords and stored records. Keep that terminal output private. Set `DATA_DIR` to a persistent private directory. One server owns each directory; the owner lock prevents unsafe concurrent instances. Never remove an active owner's lock.

`docker compose build` builds the existing application without a framework conversion. Before first start run `docker compose run --rm sentinel node scripts/setup.js`; record the newly generated credentials privately. Then `docker compose up -d`. The named volume preserves SQLite, migrations, backups and documents. The service runs as the node user, drops capabilities and exposes only host loopback. `/api/health` and `/api/ready` support probes. Docker execution must be verified on a Docker-enabled host; configuration alone is not a successful deployment result.

For reviewed local synthetic policies, set `POLICY_FILE` to an operator-owned JSON array using the contracts in `src/policy-runtime.js` and fixtures in `tests/policy-runtime.test.js`. Never mark unconfirmed real issuer rules verified. There is no HTTP policy activation path. Official activation also needs an explicit independently verified source-hash configuration; the CLI defaults to none. Historical policy replay appends an evaluation and leaves the current assessment unchanged. Automated compliance classification never grants administrative approval.

Private storage uses immutable UUID objects, exclusive writes, file flushing and SHA-256 verification on read. On startup, interrupted/unreferenced objects move to `recovery/orphans`; review them before any manual deletion. Missing/corrupt committed objects fail closed. A replacement storage adapter must implement `src/contracts.d.ts` and the local storage contract tests. S3 is an optional future implementation, not a configured integration.

Back up the database and private objects together while the service is stopped; retain migration backups and verify restoration in a separate directory before replacement. Production deployment still requires managed TLS, environment-specific host allowlisting, private volume ACLs/encryption, independent backups and issuer/bank acceptance. Child PDF/OCR processes have resource/time bounds; they are not operating-system security sandboxes.
