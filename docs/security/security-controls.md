# Security controls and operating limits

Current code/test evidence: [Phase4C report](../phase-4c-security-report.md), [traceability](../requirements/traceability.md) and [implementation progress](../implementation-progress.md). Final local186-test/21-browser/OCR/load/native-install acceptance passes; see [completion report](../phase-3-4-completion-report.md). Historical reports do not supersede these current controls.

Implemented: salted scrypt; digested random sessions/CSRF; absolute expiry, revocation and post-await live authorization; five tenant/assignment/authority-scoped roles; password rotation; encrypted TOTP enrollment/recovery/anti-replay/throttling; required-role setup; recent step-up; strict uploads/private hash-checked storage/protected page images; both-path scanner boundary with explicit missing/unavailable classification and optional fail-closed policy; reduced child environment and bounded processing; immutable correction/evaluation/source history; exact financial values and guarded revisions; independently checked source-bound internal decisions; stable bounded pagination; correlated scrubbed audit outcomes; HMAC audit chain/root/checkpoint verification; stopped-source signed backup and tested isolated restore.

All final banking/issuer authority remains independent. Synthetic or sandbox results never become confirmed bank information. Policy/applicability uncertainty blocks sensitive administrative outcomes. ClamAV contract tests are real TCP adapter tests, not actual engine/malware certification. Required scanning and production custody must be configured; unscanned is never labelled clean.

Default local key/checkpoint placement does not prove Windows ACLs, encryption or independent protection. HMAC authenticity relies on trusted key/checkpoint/code/OS custody; legacy pre-enrollment history and a never-checkpointed lost tail cannot be retrospectively authenticated. Audit verification does not sign every mutable DB field. Backups exclude keys and are not encrypted archives. Child heap/time/concurrency bounds are not OS filesystem/network isolation or a total-RSS cap. SQLite is single-owner; no distributed throttling/leases/shared objects are claimed.

Patched Node22.23.4+Node22.x is the qualified CLI/deployment baseline. The old host runtime remains untouched; final tests use a checksum-verified workspace-local runtime. The approved public dependency audit reports0 known package vulnerabilities; that does not cover runtime/OS vulnerabilities or unknown flaws. Explicit statement pinning also addresses the older Node iterator GC defect, with deterministic forced-GC regression evidence.

No live Setu consent/product test, real issuer confirmation, independent penetration/ASVS/WCAG certification, real-bank OCR accuracy, executed Docker deployment or remote CI result is claimed. Production requires TLS/Host/private-volume protection, real scanning, independent keys/checkpoints/backups and external financial/regulatory/security acceptance. No secret values belong in source, logs, browser analytics or document worker environments.
