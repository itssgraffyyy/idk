## Local versus production readiness

Local workflows remain explicit about trust. Synthetic/contract policies and mock/sandbox deposits are not issuer/bank authority. Application completion does not approve unattended financial/regulatory automation. Actual real AICTE confirmation, bank release and external account-aggregator consent/data acceptance are unavailable. User explicitly authorized Setu contract tests without credentials.

Production additionally requires current supported runtime rollout, TLS/Host and private volume ACL/encryption, actual scanner configuration/operation, independently protected signing/encryption keys and audit checkpoints, independent backup media/drills and operational security review. Document children are bounded and credential-minimized but not OS filesystem/network sandboxes. HMAC audit verification does not authenticate every mutable DB field or history preceding its enrollment; never-checkpointed lost tails and compromised key/code/OS custody remain outside its guarantees.

One SQLite owner process, synchronous bounded queries, two OCR children and local private storage are deliberate tested constraints. Distributed app/worker deployment or scope beyond500-case/10000-event overview bounds requires measured design for shared relational database/storage and leased workers. PostgreSQL is justified by such deployment/scale needs, not by Phase3 naming or JavaScript appearance. No Next.js/FastAPI/graph-database migration is necessary for these local domain contracts.

Docker/Compose and CI are configured, but Docker is unavailable on this host and no remote CI/push has occurred. Consented representative real-bank documents, calibrated recognition confidence and representative human productivity/accessibility studies remain external validation. Limited synthetic OCR and scripted tasks do not establish those claims.
