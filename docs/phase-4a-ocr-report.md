# Phase 4A OCR evaluation — development baseline

The original reported 85% aggregate included correctly absent fields. The archived audit's present-field baseline was 18/18 for reference, amount, bank and both dates, but 0/18 IFSC. Later Phase 1/2 results separately report IFSC 17/18 (V1), 11/15 present (V2), 9/12 (V3), with other V3 fields 12/12. Those corpora are now regression data; new held-out performance must come from V4.

V4 was committed as abecded before recognition edits: 42 synthetic documents (18 development, 12 validation, 12 untouched held-out). Original 48 PNG hashes remain fixed. Baseline source is independently available in the detached .scratch/ocr-baseline checkout at abecded. Its node_modules junction reuses the same pinned installed dependencies; no main project files were replaced or reset.

Genuine baseline recognition completed all 30 development/validation samples with zero processing failures. Per-field present matches: reference 18/30; amount 18/30; bank 18/30; IFSC 24/25; issue and maturity dates each 18/30; institution 17/30; depositor 15/25; branch 18/30; currency 15/25; explicit instrument type 0/30 (unsupported extraction). All five intentionally conflicting IFSCs were withheld for review. Twelve reference and bank values, thirteen institution values and ten branch values were incorrect unflagged candidates. Raw results and worker resource measurements are retained in evaluation/phase-4a/baseline-dev-validation.json and its per-document journal. This is a synthetic parser/proposal benchmark, not user acceptance or bank verification.

Error inspection shows genuine OCR successfully read both columns, but the label parser consumed the following labelled field as part of the first value. E.g. a reference included the following deposit amount; bank included the following IFSC; institution included the depositor. This justifies field segmentation against actual recognized labels/word boxes, rather than changing recognition to match truth. A validation IFSC was read HDFCo0001234 and correctly withheld; a rotated institution name was read Academy 277 rather than Academy 27. Do not silently replace identifier/name characters.

The archived remaining V2 IFSC fragments contain blank lines between a four-letter bank prefix and the seven-character suffix. The old parser only looks at the immediate next line, losing three genuine fragments. Any bounded line joining must preserve both source fragments and remain review-required when layout is uncertain. Other archived failures are visual glyph confusion (O/0, I/1 and related characters), not missing OCR execution. The V4 held-out partition has not been recognized or inspected for tuning.

Resource measurements use a benchmark-only wrapper around the real worker with secret-minimized environment and unchanged recognition. CPU is process delta; cold latency includes worker startup; warm jobs reuse at most 25 documents per worker. OS filesystem cache is uncontrolled. The 384 MiB argument limits V8 old space, not total native/WASM/RSS; measured peak RSS is reported separately and can exceed that value. No production SLA or calibrated confidence is claimed.

Next: improve multi-field segmentation/provenance, explicit type extraction and bounded blank-line IFSC fragments; evaluate actual ROI OCR for remaining glyph errors using development/validation only. Preserve raw OCR and review alternatives. Freeze revised recognition before the first held-out recognition; run both frozen baseline and revised code only after that freeze and do not tune from their held-out results.
