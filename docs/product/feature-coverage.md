# Product coverage and integration

27 October2026. Local Phase3–4 capabilities are implemented in the existing application; final whole-suite/browser/deployment/load acceptance is running. Historical milestone counts are not substituted for final results. Source authority and production readiness remain separate.

| Capability | User/problem/workflow | Data and permission boundary | Failure behavior / evidence |
| --- | --- | --- | --- |
| Guided saved submission | Institution uploads first, accepts selected proposals and resumes a saved draft | Institution/obligation profile and private versioned draft bytes; owner/session/tenant/revision checks | Invalid readiness preserves draft; source changes require reconfirmation; submissions tests and browser |
| Evidence-to-resolution | Institution/reviewer understands changed, resolved, new and remaining findings in the case | Immutable current/prior evaluations and exact source IDs/fields | Full recomputation fallback explicit; no auto-approval; operations/applicability tests and resolution browser |
| Structured clarification | Reviewer asks precisely; institution edits only disputed facts | Finding-linked request, selected attachments, immutable conversation and review history | Stale revisions/invalid or unrelated corrections rejected; operations tests and browser |
| Protected evidence workspace | Reviewer compares declaration/document/provider and opens exact historical evidence | Private version/page/geometry/method/confidence/correction references; post-read session and selected-request checks | No browser execution of document active content; viewer/PDF/storage authorization tests and browsers |
| Work queues and reminders | Responsible users see actual pending actions and explicit deadlines | Current stage/findings/maturity, current access predicate, immutable opt-in deliveries | Deduplication, role/assignment revocation, stable cursors, scheduler tests/browser; no unsolicited external messaging |
| Financial continuity | Institution/reviewer tracks dates and proposed replacement without pooling | Independent instrument/obligation IDs, predecessor/successor and version-bound evidence | Gaps/duplicates/holder conflicts/unknown evidence remain review; no maturity-as-release; continuity/lifecycle tests and browser |
| Conditional clearance | Authorized departments review selected evidence and prerequisites | Versioned bounded DAG, scoped grants, immutable request events and snapshot-bound maker/checker | Missing/unknown/stale/withdrawn/rejected inputs block decisions; independent checker and reopening tests/browser |
| Policy explanation and replay | Reviewer explains sources, versions, applicability and uncertainty | Frozen configuration capsules, exact facts/evidence, rule/exception/review references | Official sources default unverified; declared/registered programme conflicts force review; policy/procedure tests and browsers |
| OCR improvement | Institution/reviewer receives genuine, reviewable proposals | Frozen development/validation/held-out42 raster corpus and original48, per-page source geometry | Conflict withholding, retained raw OCR and corrections; per-field/error/review/resources in phase-4a-ocr-report.md; no real-bank accuracy claim |
| Financial adapters | Reviewer distinguishes branch reference from deposit evidence | Real pinned IFSC/offline adapter and explicit MOCK/Setu sandbox contracts | Consent/outage/malformed/stale/partial responses tested end-to-end; no live bank verification |
| Relationships and what-if | Authorized case user explores conflicts and proposed changes in context | Relational graph, legal self-declarations, frozen immutable scenarios, existing full-case authorization | Bounded/private signals, exact replay or explicit incompatibility; no live operational mutation; analysis tests/browser |
| Identity, audit and recovery | Account owner/auditor/operator protects access and recovers service | Encrypted TOTP/recovery/session assurance; HMAC audit root/seals/checkpoints; private hash-checked backups | Throttling/revocation/tamper/truncation/atomicity/concurrent verification/restored-start tests; trust/custody limits disclosed |
| Operational overview | Each role identifies evidence, maturity, clarification or changed-input attention | Actual currently accessible cases; compact registry preview and case links | Retry/queue fallback, bounded queries, source-safe labels; analytics tests and mobile keyboard browser |
| Analytics and optional measurement | Institution/reviewer/supervisor inspects backlog/timing and self-selected workflow effort | Scoped UTC history/current inventory; enum/duration/count measurements, no sensitive values | Oversize413, unknown/null timings, current assignment revocation, read-only auditor; no invented statistics or productivity gain |
| Infrastructure | Operator installs and runs one private local service | Existing Node/SQLite single owner, bounded workers, private storage contract, checksum migrations | CI/container configuration; actual native clean-start/load/full acceptance pending separately; no distributed-scale claim |

The UI retains purpose-specific existing navigation and merges related evidence, lifecycle, administrative decisions, history/help, relationships and scenarios into their case workflow. Secondary analytics/measurement content is collapsed by default. Mobile navigation, keyboard focus/skip link, source text contrast and responsive tables are exercised. No parallel portal, standalone graph product, graph database or mandatory paid AI service was introduced.
