# Departmental clearance implementation checkpoint

27 October 2026. Local Phase 3C work; final acceptance pending. No actual bank release or official procedure authority is established.

The existing server and portal now support trusted server-configured, versioned clearance DAGs. Requirements have applicability conditions, departments, mandatory/optional status, prerequisites and selected evidence kinds. Missing applicability facts require review; cycles, unknown dependencies and unsupported schemas are rejected. Synthetic fixtures remain explicitly SYNTHETIC. UNVERIFIED_OFFICIAL procedures cannot satisfy approval readiness.

Schema 16 adds immutable authority/case/entity event streams with revision/lineage guards. Procedure registration and activation retain exact content/hash and reasons; reusing a version with different content is rejected. Existing migrations, financial declarations, document versions, hashes and evaluations remain unchanged. Current grants are separate from normal case access. An unassigned department officer can open only their assigned request and the explicitly shared immutable source versions. Revocation, reassignment, disabled accounts, another authority, a newer document/input revision or procedure binding invalidates response authorization. Full-case permissions are not broadened.

Assigned reviewers request or refresh/reassign parallel reviews and withdraw requests; granted department reviewers independently accept or record objections. Requests bind to current input, case/instrument/obligation revisions, selected document identities/hashes, regulatory context, evaluation and trusted policy configuration. Pending, stale, rejected or withdrawn mandatory responses block approval. Final proposals bind the current clearance/grant/procedure/source snapshot and require a distinct active supervisor checker under a transaction. Concurrent requests/responses/decisions use immutable lineage/revision constraints; only one current internal decision is recorded. Historical proposals and decisions remain available.

Internal approval readiness also checks instrument source/extraction, unresolved high/critical findings, open clarifications and matching confirmed synthetic operational policy. These controls never authenticate a bank or turn synthetic policy into official authority. Reject/referral outcomes can record unresolved evidence rather than falsely approving it. The financial obligation and external release remain independent. A supervisor can close a current internally decided case; explicit reopening preserves history and starts fresh evidence/clearance review. Stale proposals can return through guarded reevaluation instead of leaving the case stranded.

The existing case workspace exposes blockers, current/history decision labels, binding, selected-document request controls, maker/checker actions and scoped history. Department navigation contains trusted activation/grant administration and a paginated request queue with selected downloads and responses. Institution views omit confidential response text, grant identities and final snapshot details. Operational clearance-delay reminders reuse opt-in settings, immutable delivery provenance and deduplication; no statutory deadline or external email delivery is implied.

Configuration: PROCEDURE_FILE points to a local JSON array validated before opening the database. No default synthetic procedure is activated in normal startup. tests/support/clearance-fixtures.js is explicitly fictional test configuration. Policy configuration remains governed by existing trusted POLICY_FILE/verification safeguards. Real departmental procedure and issuer confirmations remain external dependencies.
